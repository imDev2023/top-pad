# Top-pad

A fair-launch token launchpad on Solana, built on Meteora's pools.
The product is named **Heat** ([#65](https://github.com/imDev2023/top-pad/issues/65), formerly Greenflag); the code, its packages, Workers and database keep the working name `top-pad`.
The owner's original brief is `resources.md`; the project's terms are in `GLOSSARY.md`.

The build follows **`docs/spec.md`**, the one build-ready spec (decisions in `docs/adr/0001` to `0007`), as tickets labelled `build` (#39 to #64), sub-issues of the map wired with native blocking edges; the open ones with no open blocker are the frontier.
Each build ticket lands as its own PR, which the session merges itself once the ticket's devnet demo works end to end and CI is green (owner, 2026-10-29): `main` is fast-forwarded to the PR's head, so the commits keep the SHAs tickets cite; if `main` has moved, rebase the branch and wait for CI on the new head first.
One ticket per session (owner, 2026-10-31): once its ticket is merged and closed, a session updates the map and hands off to a fresh session with the `next-session-prompt` skill instead of starting the next ticket, so no session runs on toward the 1M-token context window.
The wayfinder map (GitHub issue #1, label `wayfinder:map`) indexes every decision and its `## Next` section names the next unit of work.
Start any session by reading that section: `gh issue view 1 --repo imDev2023/top-pad`.
The product stays separate from Stoker; merging is revisited only after the devnet cohort ([ADR 0001](docs/adr/0001-separate-product-from-stoker.md)).

For anything about Jupiter or Meteora, read the owner's canonical knowledge base first, not this repo and not the web: `/Volumes/Farhan/Work Folder/Dev/AI/Research-Projects/jupiter-meteora` locally, or https://github.com/imDev2023/jupiter-meteora-resources in the cloud.

## The build

A pnpm monorepo shaped like Stoker's: `apps/api` (Hono on Workers), `apps/web` (Next.js 16 on Workers through OpenNext, a pure client of the API), `apps/vision` (Vamp Shield's vision service, PDQ and SSCD in a Python Cloudflare Container), `packages/*` (`contract` the zod API contract, `db` Drizzle and its migrations, `clients` the Codama-generated Kit clients, `chain` Heat's own addresses per cluster and the Instant launch's instructions, `meteora` the only home of web3.js v1 and the config generator, `vamp-shield` the text and image rules and the folded keys, `indexer` the decoding, trades and candles, `arweave` and `jobs` copied from Stoker commit `43e196b`), `programs/*` (the Anchor workspace) and `tests/*` (`devnet` and `ui`, both run by hand, and `x-stand-in`, a stand-in for X's OAuth).

- `docker compose up -d` starts the local Postgres (port 5452); `pnpm lint`, `pnpm typecheck` and `TEST_DATABASE_URL=postgres://toppad:toppad@127.0.0.1:5452/toppad pnpm test` are what CI runs, each test file on its own throwaway database.
- `pnpm programs` builds `tests/dbc-stand-in`, `tests/lock-stand-in` and `tests/damm-stand-in` (our stand-ins for DBC's partner fee claim, pool creation, swap, surplus and leftover, for Jupiter Lock's `create_vesting_escrow_v2` and for DAMM v2's `claim_position_fee`, never deployed, which the programs' LiteSVM tests load in their places, so they are built first: `anchor build`'s IDL step compiles those tests), then the fee program and then both (the Fair Open tests embed `fee.so`, and `anchor build` takes programs in no fixed order), and copies both IDLs to `packages/clients/idl` (CI fails if the build changes them); then `pnpm test:programs` runs their LiteSVM tests.
  `direnv exec . pnpm test:devnet` runs `tests/devnet/src/*.test.ts` against devnet, each file's header saying what it proves (about 0.4 SOL a run from Heat's devnet bank, signed with the keeper and admission keys only this Mac holds; a Fair Open's late open makes it about 20 minutes).
  Its Graduation test graduates on devnet's rehearsal config (`CLUSTERS.devnet.rehearsal`, the Instant config with a 0.25 SOL target, about 0.08 SOL a run); `GRADUATION=real` uses the Instant config and costs about 2 SOL, the fifth of the target a graduated pool locks forever.
- A program is deployed only from a verified build (spec 5.2 records the fee program's): `solana-verify build --library-name <name> --arch v2 --cargo-build-sbf-args="--tools-version v1.57"` (0.5.2, in `~/.local/share/solana-verify-0.5.2/bin`; the flags match `pnpm programs`) in a clean clone of the commit, `solana program deploy` of that binary with `--program-id target/deploy/<name>-keypair.json --upgrade-authority ~/.config/top-pad/devnet/upgrade-authority.json --keypair ~/.config/top-pad/devnet/bank.json` (the bank pays the buffer and the rent, and extends a grown program's account, which the CLI does itself), then `solana-verify verify-from-repo -y -u devnet` with the same flags, `-k` the upgrade authority and `--commit-hash` the full hash (a short one fails to check out), which rebuilds the pushed commit from GitHub and records the verification on chain.
  `pnpm --filter @top-pad/chain fee-config devnet [--send]` sets the fee program's `FeeConfig` with the upgrade authority, and `fair-open-config` the Fair Open program's `ProgramConfig`.
- A creator schedules a Fair Open from `/launch`, signing the schedule and its 64-rung ladder in one approval, and the keeper's Workflow opens it (below); the scripts still schedule and open one by hand, Heat's bank the creator: `pnpm --filter @top-pad/chain fair-open devnet [--in <seconds>] [--min-raise <SOL>] [--send]` signs the ladder into `~/.config/top-pad/devnet/ladders/<launch>.json`, and `fair-open-open devnet <launch> [--send]` waits for the open, sends the rung the pot covers, pushes every seat and closes the nonce.
  Every rung and push compresses through Heat's shared lookup table, frozen, so a new address means a new table (`lookup-table`, its address in `@top-pad/chain`).
- Stock-priced coins (ADR 0007, #84): `pnpm --filter @top-pad/chain quote-check [--out <file>]` reads every DBC TokenBadge on mainnet (one filtered `getProgramAccounts`, which the public endpoint serves) and checks each mint with `quoteVerdict`, read-only; on 2026-11-03 it found 3,126 badges, 1,476 of them xStocks (all 8 decimals, one extension set, every one passing), 515 with a Scaled UI multiplier other than 1, from 0.1 to 10.02.
  Devnet's stand-in xStock, `DEVNET_XSTOCK_STAND_IN`, was made by `xstock-stand-in devnet --send` with NVDAx's extensions, the bank holding every issuer power; DBC takes it only once Meteora badges it on devnet.
  `xstock-multiplier devnet <multiplier> [--send]` sets its Scaled UI Amount multiplier, effective at once, as an issuer does on a split; set it back to 1 after a run.
  Pages show every amount and price through the quote's multiplier in force now, the API answering raw units and unscaled prices with `quote.multiplier` (#90); `GET /quotes` is what the launch form's picker offers, read from the chain.
  The Fair Open program's quote manager (`~/.config/top-pad/devnet/quote-manager.json`, its address in `CLUSTERS`) writes each quote's `QuoteSettings`; `pnpm --filter @top-pad/chain quote-settings devnet [--send]` names it with the upgrade authority and writes SOL's.
  Any quote's Fair Open config must equal Heat's SOL one in every byte of `dbc::CONFIG_SHAPE`, so a new config pair comes only from the generator with the SOL config's every other setting.
  A `ProgramConfig` made before the quote manager is 32 bytes short and reads as nothing in the upgraded program, so a program deploy that adds a field to it is followed at once by the script that grows it: until then deposits and schedules fail.
  Devnet's Circle USDC (#88), an SPL Token quote DBC takes with no badge, comes from `pnpm --filter @top-pad/chain devnet-usdc devnet <SOL> [--send]`, which swaps the bank's SOL through Meteora's devnet DAMM v2 pool, since Circle's faucet asks a person for a captcha; a quote's config pair comes from `pnpm --filter @top-pad/meteora configs devnet --quote <mint> --target <raw units> [--send]` and its `QuoteSettings` from `quote-settings devnet --quote <mint> --fair-open <config> --instant <config> --step <raw units> --send`, by hand; the band job does both itself now (#89, below).
  The band job (#89, spec 3.2 and 10.2), `quote-band` in the API's five-minute cron and `@top-pad/quotes`, keeps every quote in `CLUSTERS.<cluster>.quotes` (mainnet: SOL and the cohort's 22 xStocks, which `quote-check` also checks against the chain) inside the 10% band at its latest price, making a new pair from the generator and naming it with the quote manager key (Secrets Store `top-pad-devnet-quote-manager-key`); the keeper pays, about 0.012 SOL a pair, never below its float's floor; `quote_config_pairs` keeps every pair a quote has had, since the chain names only the current one.
  Read what it did in `job_runs` (`job = 'quote-band'`, the summary per quote) with `ops/devnet-db/devnet-db psql`, the devnet database being on this Mac (below).
  `direnv exec "<main checkout>" pnpm exec vitest run src/quote-band.test.ts` in `tests/devnet` runs the same job against the deployed program and the devnet database with USDC's price overridden 15% low, so it moves the deployed USDC settings twice and makes two real pairs (about 0.05 SOL from the bank); the deployed cron would bring them back within five minutes anyway.
  `tests/devnet/src/fair-open-usdc.test.ts` runs a Fair Open in that USDC (about 0.6 USDC moved and returned); `pnpm exec tsx tests/devnet/src/fair-open-recover.ts` lists every Fair Open launch left on devnet with the bank's depositors' holdings, and `fair-open-recover.ts <launch>` fails, refunds and closes one a stopped run left, sweeping its depositors' quote and SOL back to the bank.
  The program's allocation must equal `@top-pad/chain`'s reference to the lamport: both test suites read `packages/chain/src/fixtures/allocations.json`, which `pnpm --filter @top-pad/chain allocation-cases` writes, and only when the rules change.

  The protected set is the cron's: `protected-trending` every minute, `protected-lists` then `protected-images` at minute 2 of each hour (`job_runs` keeps each run's summary); Jupiter is read with `top-pad-devnet-jupiter-key` from Secrets Store, made from the owner's shared `JUP_API_KEY` on 2026-11-02.

## Traps

- Research findings live on `research/<name>` branches, pushed and never merged, so `main` does not hold them; read one with `git show origin/research/<name>:research/<name>.md`.
  Prototypes live the same way on `prototype/<name>` branches (`fair-open-creation-tx`, `screens-mockup`).
- An agent started with worktree isolation is refused any git or gh command its guard cannot prove stays in its own worktree: `cd` followed by git, loops, `source` or `.` of an env file, and even `git -C` on its own worktree path (likely the space in `Work Folder`).
  What works: one plain command per call, plain `git <cmd>` from the worktree itself, `git -C /private/tmp/claude-501/...` read-only commands on clones in the scratchpad (allowed in `~/.claude/settings.json`), and API keys through `direnv exec "<this folder>" <cmd>`.
- Auto mode refuses some writes outright: a batch of `gh issue edit` calls across many tickets (2026-10-28), at times a single `gh issue comment` (2026-11-02), a force-push even to a research branch until the owner says yes, deleting a branch, even a merged one, and Cloudflare secret writes, `wrangler secret put` and creating the Secrets Store alike (2026-10-29).
  Write a comment's body to the scratchpad with the Write tool first, never in the same Bash call as the `gh` command: a refused call writes nothing, so the owner's `! gh ... --body-file <path>` then finds no file.
  Hand the owner one `!` command, or one batch drafted in the scratchpad, reading any secret through `$(cat <file>)` or a pipe so it never lands in shell history; refetch an issue's body just before writing it, so a newer edit is not overwritten.
  Creating a Secrets Store secret is the exception on this Mac: a rule in the local `.claude/settings.local.json` allows `env -u CLOUDFLARE_API_TOKEN pnpm exec wrangler secrets-store secret create` (owner, 2026-10-30), so run it from `apps/api` with `--value "$(cat <key file>)"` before handing the owner anything.
- A PR body's `Closes #N` closes the ticket when `main` is fast-forwarded, and `gh issue close --comment` on a closed ticket drops its comment: post the closing record with `gh issue comment`.
- `wrangler dev` resolves names through the first nameserver in `/etc/resolv.conf`, not through macOS's resolver as curl does: on 2026-11-02 that was the router's IPv6 link-local address, which did not answer, and every outbound fetch of the local API (Helius, the public RPC, any host) timed out after 10 to 15 s while curl answered in 0.24 s, so no local e2e run could launch.
  The vision Container under `wrangler dev` fetches through wrangler's egress proxy, which resolves the same way, so the protected set's image batch fails locally too; a launch's own image check, which fetches nothing, works.
- Every Fair Open's coin is a protected Heat coin from its open, and an Instant coin from 100 holders, until 7 days below the activity bar (spec 6.2): a later launch with its ticker, its name (folded) or its picture is refused.
  So a test that launches must never reuse a ticker, a name or a picture: the UI specs draw both per run (`uniqueCoinImage`, `runName` in `tests/ui/src/steps.ts`), and the old shared fixture picture is gone, since dozens of devnet coins carry it.
  A Fair Open's teaser is read word by word, folded, against the same live set, so ordinary words fail as coins join it (#93: "one" as $ONE and "10" as IO on 2026-11-04): a spec's teaser is a word drawn for the run, never fixed text and never the coin's own ticker, which the calendar would show before the open.
  Check with `dig @<first nameserver> example.com`; it is the network's setup, not the code's, and the deployed site is unaffected.
- A transaction the indexer has run its handler on is never indexed again (reconciliation and the socket skip it), so one indexed while its list of Heat's configs was older than the transaction's config is lost: the handler reads the list again when a transaction registers a coin, makes a pool or swaps on a config it does not hold (#90).
  Code that indexes outside the Durable Object (`reindex`, the window claim's sweep) must load every config with `loadHeatConfigs`, or a coin priced in USDC is passed over.
- Anything that reads the chain in the background shares Helius's free tier with launches and trades: Bundle Radar's funding scans space their reads 250 ms apart, read a bounded number a time, and leave activity indexed late to the case job, because the first version, triggered by every buy reconciliation caught up on, scanned the bank's long history and starved the API's own calls.
- Solana's public mainnet endpoint (`api.mainnet-beta.solana.com`) allows about 10 calls of each method per 10 s (`getBlock` fewer), counted per method, and answers more with 429 and `retry-after: 10`; each element of a JSON-RPC batch counts as a call, so batching gains nothing (`tests/radar-eval/src/rpc.ts` paces each method on its own).
  Mainnet carries version 1 transactions (2026-11): a read asking `maxSupportedTransactionVersion: 0` is refused with -32015, and a `getBlock` holding one fails whole; the indexer's reads still ask for 0, fine on devnet and a mainnet item (spec 16).
- Of the RPC endpoints in `global.env` only the shared Helius key serves Solana devnet (the Chainstack and Validation Cloud URLs are other chains', QuickNode has a token but no endpoint), on a free tier that sends 1 transaction per second and is rate-limited when agents run in parallel (spec 10.5).
  Solana's public endpoints answer a Worker with 403, "Your IP or provider is blocked", even under `wrangler dev` (2026-10-29), so the API always needs `RPC_URL`, while Node code such as the tests defaults to the public `api.devnet.solana.com`, which answers bursts with 429 and at times refuses WebSockets: send through `tests/devnet/src/devnet.ts`, which retries on 429, confirms over HTTP and reads the chain's clock from the Clock sysvar (the endpoint at times cannot serve a fresh slot's block time), and stagger on-chain-heavy work.
- `turbo-gateway.com` serves a fresh Turbo upload at once, `arweave.net` only once Turbo has bundled it onto Arweave, minutes later (spec 16), so coins' metadata URIs name `turbo-gateway.com`.
  Its GraphQL lists a fresh upload at once too, by its tags and its owner (#50): a sealed Fair Open's items are signed by a one-time key with only `Content-Type`, never by the keeper key or with Heat's tags, or every sealed coin shows 15 s before its open.
