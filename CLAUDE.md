# Top-pad

A fair-launch token launchpad on Solana, built on Meteora's pools.
The product is named **Heat** ([#65](https://github.com/imDev2023/top-pad/issues/65), formerly Greenflag); the code, its packages, Workers and database keep the working name `top-pad`.
The owner's original brief is `resources.md`; the project's terms are in `GLOSSARY.md`.

The build follows **`docs/spec.md`**, the one build-ready spec (decisions in `docs/adr/0001` to `0007`), as tickets labelled `build` (#39 to #64), sub-issues of the map wired with native blocking edges; the open ones with no open blocker are the frontier.
Each build ticket lands as its own PR, which the session merges itself once the ticket's devnet demo works end to end and CI is green (owner, 2026-10-29): `main` is fast-forwarded to the PR's head, so the commits keep the SHAs tickets cite; if `main` has moved, rebase the branch and wait for CI on the new head first.
One ticket per session (owner, 2026-10-31): once its ticket is merged and closed, a session updates the map and hands off to a fresh session with the `next-session-prompt` skill instead of starting the next ticket, so no session runs on toward the 1M-token context window.
The wayfinder map (GitHub issue #1, label `wayfinder:map`) indexes every decision and its `## Next` section names the next unit of work.
Start any session by reading that section: `gh issue view 1 --repo imDev2023/top-pad`.
The product stays separate from Stoker; merging is revisited only after the devnet cohort ([ADR 0001](docs/adr/0001-separate-product-from-stoker.md)).

For anything about Jupiter or Meteora, read the owner's canonical knowledge base first, not this repo and not the web: `/Volumes/Farhan/Work Folder/Dev/AI/Research-Projects/jupiter-meteora` locally, or https://github.com/imDev2023/jupiter-meteora-resources in the cloud.

## The build

A pnpm monorepo shaped like Stoker's: `apps/api` (Hono on Workers), `apps/web` (Next.js 16 on Workers through OpenNext, a pure client of the API), `apps/vision` (Vamp Shield's vision service, PDQ and SSCD in a Python Cloudflare Container), `packages/*` (`contract` the zod API contract, `db` Drizzle and its migrations, `clients` the Codama-generated Kit clients, `chain` Heat's own addresses per cluster and the Instant launch's instructions, `meteora` the only home of web3.js v1 and the config generator, `vamp-shield` the text and image rules and the folded keys, `indexer` the decoding, trades and candles, `arweave` and `jobs` copied from Stoker commit `43e196b`), `programs/*` (the Anchor workspace) and `tests/*` (`devnet` and `ui`, both run by hand, and `x-stand-in`, a stand-in for X's OAuth).

- `docker compose up -d` starts the local Postgres (port 5452); `pnpm lint`, `pnpm typecheck` and `TEST_DATABASE_URL=postgres://toppad:toppad@127.0.0.1:5452/toppad pnpm test` are what CI runs, each test file on its own throwaway database.
- `pnpm programs` builds `tests/dbc-stand-in`, `tests/lock-stand-in` and `tests/damm-stand-in` (our stand-ins for DBC's partner fee claim, pool creation, swap, surplus and leftover, for Jupiter Lock's `create_vesting_escrow_v2` and for DAMM v2's `claim_position_fee`, never deployed, which the programs' LiteSVM tests load in their places, so they are built first: `anchor build`'s IDL step compiles those tests), then both programs, and copies both IDLs to `packages/clients/idl` (CI fails if the build changes them); then `pnpm test:programs` runs their LiteSVM tests.
  `direnv exec . pnpm test:devnet` runs `tests/devnet/src/*.test.ts` against devnet, each file's header saying what it proves (about 0.4 SOL a run from Heat's devnet bank, signed with the keeper and admission keys only this Mac holds; a Fair Open's late open makes it about 20 minutes).
  Its Graduation test graduates on devnet's rehearsal config (`CLUSTERS.devnet.rehearsal`, the Instant config with a 0.25 SOL target, about 0.08 SOL a run); `GRADUATION=real` uses the Instant config and costs about 2 SOL, the fifth of the target a graduated pool locks forever.
- A program is deployed only from a verified build (spec 5.2 records the fee program's): `solana-verify build --library-name <name> --arch v2 --cargo-build-sbf-args="--tools-version v1.57"` (0.5.2, in `~/.local/share/solana-verify-0.5.2/bin`; the flags match `pnpm programs`) in a clean clone of the commit, `solana program deploy` of that binary with `--program-id target/deploy/<name>-keypair.json --upgrade-authority ~/.config/top-pad/devnet/upgrade-authority.json --keypair ~/.config/top-pad/devnet/bank.json` (the bank pays the buffer and the rent, and extends a grown program's account, which the CLI does itself), then `solana-verify verify-from-repo -y -u devnet` with the same flags, `-k` the upgrade authority and `--commit-hash` the full hash (a short one fails to check out), which rebuilds the pushed commit from GitHub and records the verification on chain.
  `pnpm --filter @top-pad/chain fee-config devnet [--send]` sets the fee program's `FeeConfig` with the upgrade authority, and `fair-open-config` the Fair Open program's `ProgramConfig`.
- A creator schedules a Fair Open from `/launch`, signing the schedule and its 64-rung ladder in one approval, and the keeper's Workflow opens it (below); the scripts still schedule and open one by hand, Heat's bank the creator: `pnpm --filter @top-pad/chain fair-open devnet [--in <seconds>] [--min-raise <SOL>] [--send]` signs the ladder into `~/.config/top-pad/devnet/ladders/<launch>.json`, and `fair-open-open devnet <launch> [--send]` waits for the open, sends the rung the pot covers, pushes every seat and closes the nonce.
  Every rung and push compresses through Heat's shared lookup table, frozen, so a new address means a new table (`lookup-table`, its address in `@top-pad/chain`).
  The program's allocation must equal `@top-pad/chain`'s reference to the lamport: both test suites read `packages/chain/src/fixtures/allocations.json`, which `pnpm --filter @top-pad/chain allocation-cases` writes, and only when the rules change.
- Heat's devnet keys live outside the repo in `~/.config/top-pad/devnet`: the upgrade authority, the treasury, the keeper key, which is also the launch key, the admission key, which signs each Fair Open deposit's admission and holds no funds (spec 10.3), and the bank, which pays for every devnet test, script and deploy; `@top-pad/chain` records the treasury's, keeper's and admission signer's addresses.
- `pnpm --filter @top-pad/meteora configs devnet` simulates Heat's two DBC configs and `--send` creates them (devnet's exist, spec 3.2); a config can never be changed, only replaced, and its curve integers come only from `packages/meteora/src/configs.ts`, never by hand: DBC refused spec 3.3's first, real-valued ones (`InvalidTokenSupply`, #40).
- `pnpm --filter @top-pad/meteora idls` refreshes the pinned IDLs from the SDK packages, then `pnpm clients` regenerates `packages/clients/src/generated` (never edited by hand; CI fails if it is stale).
- Quick trades quote with DBC's SDK maths in `@top-pad/meteora/quote`, replayed by `quote.test.ts` against `src/fixtures/swaps.json`, which `direnv exec . pnpm --filter @top-pad/meteora swap-fixtures <pool>...` records from devnet (read-only); re-record after an SDK bump.
- Locally: `DATABASE_URL=postgres://toppad:toppad@127.0.0.1:5452/toppad pnpm db:migrate`, then start the API (port 8801) and the web app (port 3110) as the `webServer` entries in `tests/ui/playwright.config.ts` do, on devnet, the only cluster with Heat's configs; `pnpm --filter @top-pad/x-stand-in dev` stands in for X on port 8890.
- `direnv exec . pnpm --filter @top-pad/tests-ui e2e` runs every page flow in `tests/ui/src/*.spec.ts` end to end with that stand-in (each spec's header says what it covers, the config's what else is real), reusing servers already up, and photographs every step into `tests/ui/test-results/shots`; `e2e:devnet` runs it against the deployed devnet site; both spend devnet SOL (about 0.55 a run, and `graduation` about 2 more, needing about 9.1 in the bank at once) and run by hand, never in CI; Playwright sets no action timeout, so a locator that never matches waits out the whole test.
  `E2E_LATE=1` makes the Fair Open fail 15 minutes after its open rather than on a missed minimum raise, about 20 minutes more.
  The Fair Open specs that wait out a 10-minute window (`fair-open-scheduled`, `fair-open-sign-at-open`) take 12 to 14 minutes each; pass a spec's file name to run one, `bundle-radar.spec.ts` rather than `bundle-radar`: Playwright matches the filter against the whole path, and a worktree's folder named after its ticket matched every spec (2026-11-02, which ran all 11).
  `bundle-radar` waits out a coin's first hour for its case, about 75 minutes, holding no SOL after its 2-minute sells; it launches again whenever its bundle misses the creation slot (Heat's launch key sends the creation, so the bundle can only race it: on 2026-11-02 two tries in three landed, timed from the submit), about 0.1 SOL a run and 0.03 a try again; its wallets derive from the bank's key and the run's name, which it logs, so a run stopped partway is swept back with `pnpm exec tsx tests/devnet/src/bundle-sweep.ts <run> <mint>`.
- The indexer is a Durable Object in the API Worker (spec 10.2): `GET /indexer` says how it stands and which version it runs, and starts it, which locally nothing else does (the cron does on devnet); `DATABASE_URL=... pnpm --filter @top-pad/indexer check-candles` compares every coin's candles with a rebuild from its trades.
- Bundle Radar (spec 6.4, 6.5): `GET /coins/<mint>/radar` gives a coin's labels with their evidence, worked out from the indexed rows; the indexer reads the Creator wallet's funding window as a coin launches or is bought in its first hour, and the cron's `bundle-radar` job reviews each coin once its first hour has ended, opening a case (`bundle_cases`, its evidence pack also in R2) when wallets linked to the Creator wallet bought 1% of supply.
- The Bundle Radar evaluation (spec 11.5, [#61](https://github.com/imDev2023/top-pad/issues/61)): `pnpm --filter @top-pad/tests-radar-eval evaluate` runs Bundle Radar's own rules (`labelBuy`, `fundingLinks`, `walletLabels` in `@top-pad/indexer`, which `radarOf` calls) over 2,000 mainnet pump.fun launches of 2026-10-25, scored against Jito's public bundle record, plus the Cryptstarter and Harmonized fleet, and writes `docs/bundle-radar-evaluation.md`.
  It reads only Solana's public mainnet endpoint and Jito's public API (no key, no transaction) and keeps what it read in `tests/radar-eval/data` (`launches.json` the list, `set.jsonl` a launch a line, `fleet.json`), so a rerun only scores; a stopped read goes on where it stopped, and `--refetch` reads it all again (about four hours on the free tier).
- Vamp Shield (spec 6.2, 10.2): `apps/vision` is the vision service, PDQ and SSCD in one Python Container (instance type `basic`) behind the API's `Vision` Durable Object, asleep 3 minutes after its last call; `docker build --platform linux/amd64 --target test apps/vision` builds it and runs its tests, as CI does, and `wrangler dev` and `wrangler deploy` build it with the local Docker (the first deploy pushed about 200 MB).
  Every launch's image is checked by it before our launch key co-signs, and an image it cannot check refuses the launch, so a local API without Docker launches nothing.
  The protected set is the cron's: `protected-trending` every minute, `protected-lists` then `protected-images` at minute 2 of each hour (`job_runs` keeps each run's summary); Jupiter is read with `top-pad-devnet-jupiter-key` from Secrets Store, made from the owner's shared `JUP_API_KEY` on 2026-11-02.
- The keeper's Workflows (spec 10.2): `InstantLaunchKeeper` sends each Instant launch's window claim at 60 s; `FairOpenKeeper` uploads a Fair Open's metadata 15 s before its open if its pot can open (`DATABASE_URL=... pnpm --filter @top-pad/db serve-times` says how soon Turbo served each), sends the rung once the chain's clock reaches the open, pushes every seat, locks the creator's coins in Jupiter Lock, collects the Tax Share once the Tax window ends and pushes it, closing every seat and then the launch; or fails the launch and refunds every seat; then closes the nonce and releases the ticker.
  `GraduationKeeper` migrates a coin whose curve completed into DAMM v2, then splits its surplus and burns its leftover; the cron claims Heat's LP fees hourly.
  `wrangler dev` runs them locally, where `curl localhost:8801/cdn-cgi/local/explorer/api/workflows/<top-pad-instant-launches|top-pad-fair-opens|top-pad-graduations>/instances` lists instances and `curl localhost:8801/cdn-cgi/local/scheduled` runs the cron, whose sweeps restart any keeper that was missed; on devnet, `env -u CLOUDFLARE_API_TOKEN pnpm exec wrangler workflows instances list <name>-devnet` in `apps/api`.
- Devnet: `direnv exec "<this folder>" pnpm deploy:devnet` migrates the Neon devnet database (`DATABASE_URL` in the gitignored `.env`), then deploys the X stand-in, the API and the web Worker, in that order; the devnet demo is https://top-pad-web-devnet.imdev2023.workers.dev, its API https://top-pad-api-devnet.imdev2023.workers.dev.
  The devnet API's one secret is `RPC_URL` (the Helius devnet URL), and its keeper and admission keys are `top-pad-devnet-keeper-key` and `top-pad-devnet-admission-key` in the account's Secrets Store; locally the e2e config passes both as vars from `~/.config/top-pad/devnet`.
  Until Heat has its own X app (owner, 2026-10-29), the devnet API links X through the stand-in's Worker, `top-pad-x-stand-in-devnet`, named by four vars in `apps/api/wrangler.jsonc`; the real app replaces them with the secrets `X_CLIENT_ID` and `X_CLIENT_SECRET`.

## Traps

- Research findings live on `research/<name>` branches, pushed and never merged, so `main` does not hold them; read one with `git show origin/research/<name>:research/<name>.md`.
  Prototypes live the same way on `prototype/<name>` branches (`fair-open-creation-tx`, `screens-mockup`).
- An agent started with worktree isolation is refused any git or gh command its guard cannot prove stays in its own worktree: `cd` followed by git, loops, `source` or `.` of an env file, and even `git -C` on its own worktree path (likely the space in `Work Folder`).
  What works: one plain command per call, plain `git <cmd>` from the worktree itself, `git -C /private/tmp/claude-501/...` read-only commands on clones in the scratchpad (allowed in `~/.claude/settings.json`), and API keys through `direnv exec "<this folder>" <cmd>`.
- Auto mode refuses some writes outright: a batch of `gh issue edit` calls across many tickets (2026-10-28), at times a single `gh issue comment` (2026-11-02), a force-push even to a research branch until the owner says yes, deleting a branch, even a merged one, and Cloudflare secret writes, `wrangler secret put` and creating the Secrets Store alike (2026-10-29).
  Write a comment's body to the scratchpad with the Write tool first, never in the same Bash call as the `gh` command: a refused call writes nothing, so the owner's `! gh ... --body-file <path>` then finds no file.
  Hand the owner one `!` command, or one batch drafted in the scratchpad, reading any secret through `$(cat <file>)` or a pipe so it never lands in shell history; refetch an issue's body just before writing it, so a newer edit is not overwritten.
  Creating a Secrets Store secret is the exception on this Mac: a rule in the local `.claude/settings.local.json` allows `env -u CLOUDFLARE_API_TOKEN pnpm exec wrangler secrets-store secret create` (owner, 2026-10-30), so run it from `apps/api` with `--value "$(cat <key file>)"` before handing the owner anything.
- A PR body's `Closes #N` closes the ticket when `main` is fast-forwarded, and `gh issue close --comment` on a closed ticket drops its comment: post the closing record with `gh issue comment`.
- `wrangler dev` resolves names through the first nameserver in `/etc/resolv.conf`, not through macOS's resolver as curl does: on 2026-11-02 that was the router's IPv6 link-local address, which did not answer, and every outbound fetch of the local API (Helius, the public RPC, any host) timed out after 10 to 15 s while curl answered in 0.24 s, so no local e2e run could launch.
  The vision Container under `wrangler dev` fetches through wrangler's egress proxy, which resolves the same way, so the protected set's image batch fails locally too; a launch's own image check, which fetches nothing, works.
- Every Fair Open's coin is a protected Heat coin from its open, and an Instant coin from 100 holders, until 7 days below the activity bar (spec 6.2): a later launch with its ticker, its name (folded) or its picture is refused.
  So a test that launches must never reuse a ticker, a name or a picture: the UI specs draw both per run (`uniqueCoinImage`, `runName` in `tests/ui/src/steps.ts`), and the old shared fixture picture is gone, since dozens of devnet coins carry it.
  Check with `dig @<first nameserver> example.com`; it is the network's setup, not the code's, and the deployed site is unaffected.
- Anything that reads the chain in the background shares Helius's free tier with launches and trades: Bundle Radar's funding scans space their reads 250 ms apart, read a bounded number a time, and leave activity indexed late to the case job, because the first version, triggered by every buy reconciliation caught up on, scanned the bank's long history and starved the API's own calls.
- Solana's public mainnet endpoint (`api.mainnet-beta.solana.com`) allows about 10 calls of each method per 10 s (`getBlock` fewer), counted per method, and answers more with 429 and `retry-after: 10`; each element of a JSON-RPC batch counts as a call, so batching gains nothing (`tests/radar-eval/src/rpc.ts` paces each method on its own).
  Mainnet carries version 1 transactions (2026-11): a read asking `maxSupportedTransactionVersion: 0` is refused with -32015, and a `getBlock` holding one fails whole; the indexer's reads still ask for 0, fine on devnet and a mainnet item (spec 16).
- Of the RPC endpoints in `global.env` only the shared Helius key serves Solana devnet (the Chainstack and Validation Cloud URLs are other chains', QuickNode has a token but no endpoint), on a free tier that sends 1 transaction per second and is rate-limited when agents run in parallel (spec 10.5).
  Solana's public endpoints answer a Worker with 403, "Your IP or provider is blocked", even under `wrangler dev` (2026-10-29), so the API always needs `RPC_URL`, while Node code such as the tests defaults to the public `api.devnet.solana.com`, which answers bursts with 429 and at times refuses WebSockets: send through `tests/devnet/src/devnet.ts`, which retries on 429, confirms over HTTP and reads the chain's clock from the Clock sysvar (the endpoint at times cannot serve a fresh slot's block time), and stagger on-chain-heavy work.
- `turbo-gateway.com` serves a fresh Turbo upload at once, `arweave.net` only once Turbo has bundled it onto Arweave, minutes later (spec 16), so coins' metadata URIs name `turbo-gateway.com`.
  Its GraphQL lists a fresh upload at once too, by its tags and its owner (#50): a sealed Fair Open's items are signed by a one-time key with only `Content-Type`, never by the keeper key or with Heat's tags, or every sealed coin shows 15 s before its open.
  Nothing about a sealed coin (name, ticker, mint, either item's id or URI) may go into an API answer, a log line or a Workflow error before the open; `fairOpenLaunches.test.ts` and `fairOpenKeeper.test.ts` search them all for it.
- Write a non-ASCII test string as `\u{...}` escapes: agents' file tools have written `\uXXXX` escapes to disk as the raw character, which puts invisible or lookalike characters in source.
- Never download, dump or commit Meteora's program binaries: Meteora suggested on 2026-10-28 (#26) that tests run against its deployed devnet programs, so Surfpool, which runs them locally, stays out too.
  Cloning Meteora's repos pulls them in anyway (`tests/fixtures/*.so`, SDK `artifacts/*.so`): read source on GitHub, or delete those files the moment a clone lands.
- Devnet SOL is scarce: CLI airdrops are refused, and faucet.solana.com gives at most 10 SOL every 8 hours (spec 11.4); the owner collects it into Heat's devnet bank, `Ew6E318g8SYCSjCUdRqcpSywRUzuFUPoxLAQWYfZD933` (`~/.config/top-pad/devnet/bank.json`).
  Nothing of Heat's spends from the Solana CLI's default wallet (owner, 2026-10-30): the scripts take `BANK_KEYPAIR` to pay from another, and a `solana` command that sends takes `--keypair` the bank.
  A run's throwaway wallets die with it, so SOL a test leaves in a program account must come back in a `finally` (`recoverDeposits` for Fair Opens): runs stopped partway lost 1.58 SOL before that (#45).
  An opened launch's seats keep their own rent until the Tax Share closes them, so the open's tests derive their depositors from the bank's key and the launch (`depositorsOf`) and settle every launch they open with `settleOpened` (lock, Tax Share, close), which a later run can also send for a launch a stopped run left open.
  After a migration lands, migrate the local database too (`pnpm db:migrate` above) before a local e2e run: an API on the old schema answers 500 and the indexer fails every insert.
- Never hard-code rent: a token account's fell from 2,039,280 to 1,488,440 lamports on devnet and mainnet in late 2026 (found in #51), so code asks the cluster (`getMinimumBalanceForRentExemption`).
  A local API left running watches devnet too, and its Workflows race the deployed keeper's: stop it before a deployed demo.
- A swap built for a wallet is simulated by the wallet's own node, which can run seconds behind, where the sniper tax is higher: set a swap's minimum from the fee of two seconds earlier, or its preflight refuses it (spec 9, screen 3, #43).
- Never send a ladder's rung that could fail on chain: a failed durable-nonce transaction still advances its nonce and voids every other rung, so the keeper sends only after a preflight at `processed` passes, never with `skipPreflight` (spec 10.2).
  A Fair Open scheduled under a local e2e run is kept only by that run's `wrangler dev` Workflow: if the run dies before the open, no keeper ever fails it (the deployed cron sees only the Neon database), and its throwaway creator's rent stays in it.
  `wrangler dev` reloads on any edit to the API or a package it bundles, and a Workflow asleep across a reload never wakes (#50): never edit them during a local Fair Open run, or its open never goes out and the run's throwaway depositors' SOL, payable only to wallets whose keys died with the run, is lost (about 0.4 SOL on 2026-11-02).
  Terminate a stuck instance with `curl -X PATCH localhost:8801/cdn-cgi/local/explorer/api/workflows/top-pad-fair-opens/instances/<launch>/status -d '{"status":"terminate"}'`, then `curl localhost:8801/cdn-cgi/local/scheduled`, whose sweep starts it again.
- A program that moves lamports by hand, as the Fair Open vault does, must let the first CPI after the move carry both accounts, or the runtime refuses it as `UnbalancedInstruction` (spec 5.3).
  A transaction's instructions, its programs' calls included, stop at 64, which caps a push at 7 seats before its bytes do, and LiteSVM panics past 38 static accounts, the most a 1,232-byte transaction can name.
- Build the programs with `pnpm programs`, never a bare `anchor build`: Anchor 1.2.1 defaults to SBPF v3, which neither devnet nor mainnet has activated (2026-10-27), and the program tests fail on a v3 binary.
  The program ids are fixed, `HeatF…` (fee) and `HeatP…` (Fair Open) ([#65](https://github.com/imDev2023/top-pad/issues/65), spec 5.1), and their keypairs exist only in this Mac's gitignored `target/deploy` and the owner's password manager (spec 10.3), so a fresh checkout builds with random ones and warns of a mismatch, which is expected: never "fix" it with `anchor keys sync`, which writes the random ids into the source.
- Anchor 1.2.1 is pinned in `Anchor.toml` (`[toolchain]`), so avm's `anchor` runs it here while the machine's default stays 0.31.1 for other projects; `avm install` switches the default, so run `avm use 0.31.1` after installing another version.
- Codama's output for the DBC IDL is not clean on its own; `packages/clients/scripts/generate.ts` fixes the IDL first (see its comment), so always generate through `pnpm clients`.
- The devnet database is Neon project `odd-firefly-70405620` (London, Postgres 17 like docker and CI), behind the Hyperdrive named in `apps/api/wrangler.jsonc`, whose query cache is off (spec 10.4); `npx neonctl` needs `--org-id org-wispy-snow-11801955` on every command or it stops at an interactive prompt.
  Its free plan's 100 compute-hours a month last only while it sleeps between requests, so anything that queries it on a timer keeps it awake: the indexer reconciles against the chain first and opens the database only for something new (spec 16).
  The cron's job rows keep it awake regardless (the five-minute jobs, and since #52 the protected set's every minute): it was active 37 of November's first 38 hours, about 180 compute-hours a month, so the free plan runs out mid-month until the owner moves it to a paid plan (spec 16).
- The Cloudflare token in `global.env` cannot use Hyperdrive or Secrets Store; the owner's wrangler login can, so run those commands with the token unset (`env -u CLOUDFLARE_API_TOKEN pnpm exec wrangler hyperdrive ...`).
  Deploys work with the token, except the API's: binding its Secrets Store secret fails with code 10021, so `@top-pad/api`'s `deploy:devnet` unsets the token itself.
- After every API deploy, `GET /indexer` should name the deploy's version: a Durable Object busy with a socket and an alarm can run the old code for minutes, so the API deploys with `--durable-objects-code-update-mode immediate` and the indexer resets itself when the Worker calling it runs another version.
  The indexer also passes over every transaction it has indexed before, so when a deploy teaches it events in transactions it already indexed (#45: `create_launch`; #46: opens and deliveries), run `DATABASE_URL=... RPC_URL=https://devnet.helius-rpc.com/?api-key=$HELIUS_API_KEY pnpm --filter @top-pad/indexer reindex <cluster> <account>`; `DEVNET_RPC_URL` is not set on this Mac, so the tests use the public endpoint.
- The owner's Discord (Meteora ticket `devlaunch-6428`, Jupiter `#dev-support`) runs in Brave, reachable through the Claude in Chrome extension, not the Discord desktop app.
